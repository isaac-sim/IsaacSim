# Changelog

## [2.2.1] - 2026-09-29
### Fixed
- "Disable self collisions" takes effect on robots that carry only the base `UsdPhysics` articulation schema.
- "Disable self collisions" takes effect under Newton as well as PhysX.
- Running a test no longer modifies the selected robot or leaves the stage with unsaved edits.
- A test reports when disabling self-collisions cannot take effect on the active physics engine.
- Stopping the timeline restores self-collisions instead of leaving them off for the session.
- A test no longer inherits the self-collision state of an interrupted earlier run.
- The timeline no longer restarts every frame when a robot reports DOFs but no tunable joints.

## [2.2.0] - 2026-08-30
### Added
- Chart value readout: a "Value Readout" section at the bottom of each Position, Effort, and dt-sweep chart reports the x value under the pointer and the value of *every* visible series as the pointer moves across the plot, instead of a single unlabeled number. It is a row per joint and a column per legend group, so a multi-joint selection is read as a table and every selected joint is listed. It is part of the chart's layout rather than a popup over it, so it never covers the traces it reports, and it sits below the plot and the axis controls, so opening it moves neither. It starts closed, keeps whatever state it was left in, and its header states what hovering the chart does. The readout resolves the pointer against the stretch of the time axis each trace is drawn across, so a trace clipped where its response diverged reads correctly inside its own span and reports no value past its end.
- Copy To PhysX / Copy To Newton in Advanced Actuator Parameters: copy the active backend's Armature, Joint Friction, and Max Joint Velocity onto the inactive backend's joint schema, for one joint or for all of them. The buttons name the backend being written and are re-labelled when the engine changes. Params the target backend already simulates at the same value are skipped, and a multi-joint copy is a single undo step. An unlimited velocity limit is copied as an authored `inf` rather than being silently dropped.

### Changed
- Editing Armature, Joint Friction, or Max Joint Velocity writes only the active backend's joint schema and leaves the other backend's authored value alone. The two solvers need different tuning, so a Newton/PhysX difference is presented as information rather than as a problem: the advanced params and their table cells state each backend's authored value and which one is in effect, in an informational colour, with no suggestion that the difference needs fixing.
- The reported effective value follows Newton's actual schema-resolver order for the live solver instead of assuming one schema per backend: under Newton an unauthored armature or velocity limit falls back to `physxJoint:*`, joint friction does not fall back at all (a PhysX-only friction is stated as ignored by Newton), and under the MuJoCo solver `mjc:*` resolves ahead of PhysX. The panel says it cannot determine the effective value rather than guessing when the solver is unknown, and reports values that are authored but never read.
- Max Joint Velocity reports when the running engine enforces a different limit than the one authored in USD, including when USD authors no limit at all, and states that velocity tests sweep to the enforced limit. Shown only while a simulation is running.
- Editing one of the three params while the timeline plays under Newton says that Newton reads them from the stage once, at the start of the simulation, and to play again to apply the edit. Newton builds its model in `ModelBuilder.add_usd` and has no USD notice handler, so the edit would otherwise look applied while nothing changed. PhysX does apply such a write to the running articulation, so nothing is said under PhysX.

### Fixed
- Panel tooltips were laid out on a single unwrapped line, so the window's right edge cut them mid-word: the per-backend explanation, which reaches the table only through the cell tooltip, ended at `... PhysX uses physxJoint:armatu`, and the copy buttons' longer text also covered the button it described. Table headers, table cells, detail fields, and both copy buttons now build a width-constrained tooltip that wraps, and the copy buttons anchor theirs below the button.
- The joint detail editor was a fixed 300 px nested scroll area holding around 500 px of content once Advanced Actuator Parameters was expanded, so Max Joint Velocity was cut mid-row and Joint Friction, the per-backend note, and both copy buttons fell below an inner fold while the panel underneath sat blank. The section is now sized to its content and scrolls with the rest of the page.
- An unauthored advanced param was distinguished from an authored one only by a grey that is unreadable in isolation -- an unauthored `0.0` looked exactly like an authored `0.0`, and the word "default" appeared only in the sentence below the field, which a table cell cannot show. The field itself now reads `0.1 (default)`, so the marking travels into the table, and it is dropped -- along with the grey -- the moment a value is authored, in the field, in the table cell, and in every other selected row a multi-row edit wrote to. Which engine's default it is named in the field's own explanation, which the table carries as the cell's tooltip; the cell has room for the number and the marker and nothing else. Those sentences are re-derived with the field, so a Max Joint Velocity dragged to `16.0` no longer sits over "Nothing is authored here, so Newton leaves this unlimited", and a line with nothing left to say is taken away rather than reworded -- as is the cell's tooltip and the field's own.
- A value the active backend reads through its fallback chain (a PhysX-authored armature under Newton) was shown like any authored value with nothing said, while friction, which has no fallback, got two lines opening "nothing is authored". The fallback now states which attribute is unauthored, which one is being read, and that an edit here authors the backend's own -- and the unauthored case is one line instead of two saying the same thing twice.
- The field read `unlimited` while the sentence under it said `no limit`. Everything now says `unlimited`.
- An unauthored Armature, Joint Friction, or Max Joint Velocity read as `0.0`, a value no engine uses. An unauthored armature showed `0.0` while Newton simulates `0.1`, and an unauthored velocity limit showed `0.0` -- "held at a standstill" -- when the truth is unlimited; the field is live, so nudging it authored the standstill for real. Each now shows what the engine will actually use, measured from the running engine where possible and otherwise taken from that engine's documented default, greyed and labelled as a default rather than an authored value, with an unauthored limit reading "unlimited". The cell stays editable, and typing a value authors it as before. A param with nothing stateable at all -- one that does not apply to the joint, an undetermined Newton solver, an engine whose joint schema is unknown -- is left blank in the detail panel as well as in the table, rather than reading `0.00` under a note saying the value cannot be read.
- The advanced params were editable, and copyable, under any physics engine, with anything that was not Newton writing `physxJoint:*`. `remotesim` is a real engine value and a failed engine query returned an empty string, so both silently authored a PhysX schema with no evidence the running engine reads it. Editing and copying are now disabled with a stated reason unless the active engine is PhysX or Newton, and nothing else names PhysX for such an engine either: the header badge reports the engine the simulation manager named, or "unknown" when it could not be read, the Source badge says nothing rather than "Physics", and the sentences about which schema is read and which values go unread are suppressed instead of being phrased about PhysX. The panel previously said "the active physics engine is not one this extension can author joint parameters for" one line above "physxJoint:armature (0.5) is not read by PhysX", under `remotesim`.
- An advanced param write that could not apply its joint schema left the field showing the typed number as though it had been saved. The field now reverts to its previous value and the failure is reported, matching what a failed copy already did.
- Chart traces were drawn with only the first series of each pair coloured: `data_colors` is per-series, but one colour per selected joint was passed for a plot holding a command trace and an observed trace per joint, so every observed trace fell through to the default grey. A joint with no recorded trajectory also shifted the remaining colours off their traces. Colours are now built per drawn series on the Position, Velocity, Effort, and dt-sweep charts.
- `WARNING_COLOR` and `FAIL_COLOR` had their red and blue channels transposed, so the "warning" colour rendered as a blue almost identical to the informational one and a "FAIL" label rendered blue rather than red. `omni.ui` packs colours ABGR.
- The Newton solver read back empty, so the header showed a bare "Newton" and the resolver order could not be determined. The solver now resolves from the stage's Newton physics scene when Newton's solver config has not initialized yet, which is the case before the first play.
- Changing the physics engine while the panel was open left it acting on the previous one, because the backend was cached at stage load and there is no engine-switch event to subscribe to. With per-backend values this stopped being cosmetic: an edit could land on `physxJoint:*` while Newton was running, and Newton reads no PhysX joint friction, so the tuning silently did nothing. The active backend is now read live for every write, and a switch is detected on the update tick, which re-reads the backend and solver, re-acquires the articulation whose physics views the switch invalidated, re-resolves the save targets, and discards responses recorded under the previous engine rather than charting two solvers in one trace. An engine that could not be *read* is not treated as an engine that changed: the simulation manager query fails transiently, and a failure against a previously known engine would otherwise have destroyed the user's recorded results, then destroyed them again when the query recovered. The panel adopts the new label so nothing keeps naming the old engine, and leaves the results and the articulation alone.
- The Armature, Joint Friction, and Max Joint Velocity columns and detail fields did not read the Newton joint schema at all, so values the URDF converter imported were invisible to the tuner. Max Joint Velocity also could not be set on a joint that had no limit yet, which is most of them, and an advanced detail field could jump to the other backend's value, or to zero, after an unrelated table edit.
- The chart readout reported only the Command series. Each trace is a separate plot, so only one of the overlapping plots won the pointer and the Observed series never reported at all; a dedicated capture layer now owns the readout.
- Hovering a chart popped up a near-empty tooltip naming a bare sample index and value, belonging to whichever single trace the pointer resolved to and disagreeing with the readout. That tooltip is built into the plot primitive itself and appears whenever a trace is hovered, so the traces are now drawn in a layer the pointer never reaches. A hovered chart fills the readout section and shows nothing else.
- The chart readout was drawn on Kit's translucent default tooltip background over the plot, so the traces behind it showed through the figures and a reading was sometimes taken from on top of the series it reported. It is now a section of the chart's own layout, styled from the chart's dark palette with near-white text.
- The readout repeated each joint's name once per legend group, which ran a multi-joint selection out of horizontal room and left some of the selected joints unreported. Each joint is now a row, named once, with a column per legend group.
- The readout section's header read "Value Readout ? hover the chart..." because it separated its title from its hint with an em dash, which the app's default font has no glyph for. The header and the readout's not-applicable cell are plain ASCII, and a test now checks that everything the readout prints is drawable by that font.
- Chart legend dots and labels were a fixed cyan/blue while the traces were drawn in per-joint colours, so the legend named a colour no trace used. Legend swatches now come from the trace colours, with one swatch per distinct colour in a group.
- Chart grid lines split the plot into equal bands regardless of the values plotted, so a line fell on zero only by coincidence and no line was a number that could be read off. On the Effort chart, where torque swings either side of zero, this left nothing marking the zero crossing and made the sign of a reading easy to misjudge. Horizontal grid lines are now drawn at round values within the current view range, the zero line is brighter than the others whenever zero is in view, and the y axis labels that zero line -- or the nearest round line when zero is off screen -- in place of the range's arithmetic midpoint, which no line was ever drawn at. The view range itself is unchanged, so the range slider, the type-in fields, and Fit Frame View still set exactly the range they report.
- Chart traces are drawn with no margin or padding, aligning them with the grid and axis labels.
- The Offset, Step Min, and Step Max columns of the Test Gains joint table were labelled "deg" for every joint. Prismatic joints keep their values in stage linear units, so their entries are now labelled "m" and no longer read as an angle.
- Disabling or hot-reloading the extension leaked the previous extension object, and Kit warned that something still held a reference to it. `omni.ui` keeps the window alive past its Python reference, so the window's visibility-changed callback retained the whole extension and every reload accumulated another copy; shutdown now clears that callback and destroys the window.

## [2.1.0] - 2026-08-28
### Changed
- The test progress bar holds just short of full while a run is going and reports elapsed time against the estimate once it overruns, reaching 100% only on completion. Snap to Limits and dt Sweep durations are estimates, so weak gains can make a run last several times longer than predicted.
- The Position chart is framed on the readable part of a diverged run rather than on the full recorded extent, since a run that diverges early leaves the response occupying a few percent of both axes. Fit Frame View still shows everything recorded.
- The charts leave a margin above and below the plotted range so a trace is not drawn flush against the top or bottom edge.

### Fixed
- A joint that diverges mid-test no longer blanks the whole Position chart. Each trace is clipped where its data stops being usable -- at its first non-finite sample, and at the point it winds up past a multiple of its own travel limits -- instead of collapsing the shared axis range. A footer note reports the clip and points at Fit Frame View.
- A clipped trace is drawn across the stretch of the time axis it actually covers, so it no longer stretches to fill the chart and appear to diverge at the end of the run, and a trace ending at the window's right edge is no longer given zero width.
- The Test Gains page explains that there are no results to chart instead of showing an empty panel beside the joint picker.
- The Position and Effort charts report when the selection is empty or carries no recorded data, rather than drawing an empty chart.
- Traces no longer outline themselves, which drew a stray vertical rule beside a narrowed plot.

## [2.0.2] - 2026-08-25
### Fixed
- Natural Frequency and Damping Ratio edits author damping in the units the joint stores it in, so a revolute joint is simulated at the requested damping ratio instead of 180/pi times it. Re-tune revolute joints whose damping was set through these fields.
- The Damping Ratio field shows a revolute joint's true damping ratio rather than a value 180/pi too small.
- Prismatic joints tuned through these fields no longer have an angular unit conversion applied to their linear gains. Re-tune prismatic and D6 `trans*` joints whose stiffness was set through Natural Frequency, which was previously authored 180/pi too small.

## [2.0.1] - 2026-08-10
### Fixed
- Running a test on a physics backend that does not provide measured joint forces (e.g. Newton) no longer floods the log with per-step errors. On such backends the Effort chart is omitted (Position charts and results are unaffected); it is shown as before on backends that report measured joint forces.

## [2.0.0] - 2026-08-03
### Added
- Redesigned Gain Settings page: a single scalable tree table of tunable joints with Ctrl/Shift multi-select and per-selection editing, a column picker that auto-selects the columns the loaded robot uses, and a per-joint detail editor for Kp/Kd (Ki for PID actuators), advanced actuator params, and a Stiffness/Damping <-> Natural Frequency/Damping Ratio toggle. Table and detail editor stay in two-way sync.
- Multi-backend gain sources: a per-joint Source selector across PhysX DriveAPI, MuJoCo-native, and Newton actuator gains. Only the active source is editable; inactive sources are shown read-only for comparison.
- Source-aware saving: a Save Target picker routes DriveAPI gains to a chosen physics layer, with opt-in mirroring into MuJoCo params and default writeback of Newton actuator gains to their own layer.
- Test Gains tab with Snap to Limits, Sinusoidal, Step Function, Stress, and a new Discretization Sweep mode. Each run leads with a scene-level verdict banner above an all-joints results table and the Position/Effort charts.

### Changed
- Show backend and solver as read-only tags reflecting the live physics engine.
- Increase base UI font sizes and exclude mimic joints from the tunable-joint list.
- The Tools > Robotics > Gain Tuner menu and toolbar action toggle the window's visibility.
- Refactor the Test Gains results panels into a shared, spec-driven builder; behavior unchanged.

### Fixed
- Robots whose articulation view cooks lazily (Newton) populate their joints once the view reports DOFs instead of showing "no joints found".
- Switching Test Gains mode clears the previous mode's results so stale rows and the verdict banner no longer linger.
- Save File posts the no-permission warning once per click and no longer opens the save dialog with an empty layer list.
